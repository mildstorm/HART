# 13. 메인 6502 ↔ U64 연결 방식 (분석 1차, 2026-11-23)

STM32 에뮬레이터에서 HART를 실기와 똑같이 돌리려면, 메인 CPU(U30)와 보조 CPU(U64)가 어떻게 주고받는지 알아야 합니다. 이 문서는 U65(U64 펌웨어)와 U45(메인 $C300·$C800 펌웨어) 덤프를 **실제로 실행되는 코드만 따라가며**(리셋·진입점부터 분기를 추적하는 역어셈블) 읽은 결과입니다.

표기: **확인** = 코드에서 직접 보임, **추정** = 코드 정황에서 유추, 회로로 아직 확인 안 함.

---

## 1. U65는 $C000(과 $E000)에 놓인다 — 기존 역어셈블리 주소 정정

| 벡터 | 값 | 뜻 |
| :--- | :--- | :--- |
| RESET | `$C000` | 롬 첫 바이트(`D8` CLD)에서 시작 (**확인**) |
| IRQ | `$2120` | 롬 밖 |
| NMI | `$0016` | 롬 밖 |

* 리셋 벡터가 `$C000`이므로 U65는 U64 버스의 **$C000–$DFFF**에 있고, 벡터를 $FFFA에서 읽으려면 **$E000–$FFFF에도 같은 롬이 비쳐야** 합니다(A13 미디코드, **추정**이지만 다른 배치로는 부팅 불가).
* [`disasm/U65_VD5.asm`](../disasm/U65_VD5.asm)은 시작 주소를 `$E000`으로 잡았습니다. 롬 안의 점프·테이블 주소(`JMP $D16E`, `LDA $C991,X` 등)는 `$C000` 기준이므로, 그 파일의 주소는 `-$2000` 해서 읽어야 합니다.

## 2. U64 로컬 버스 주소 맵 (U65 코드 기준)

| U64 주소 | 쓰임 (코드) | 판단 |
| :--- | :--- | :--- |
| `$4000–$43FF` | 리셋 시 0으로 지움, `$43C0,X` 읽기, `$43E8–$43FF` 변수 | **U68 6116의 홀수 칸** (메인 `$E000+2k+1`, 3.1절 측정) |
| `$5000–$53FF` | 리셋 시 0으로 지움, `$53C0,X` 읽기, `$53F6–$53FF` 변수 | **U68 6116의 짝수 칸** (메인 `$E000+2k`) |
| `$8000–$800C` | 13개 주소를 차례로 읽고 각각 `CMP #$FF` (눌린 키가 0) | **키보드 매트릭스 13행 스캔** (**확인**: 스캔 루프 `$CA1C–$CA99`) |
| `$8800` | 하위 4비트를 읽어 표(`$C991`, `$C9A1`)로 변환 | 스위치/모드 입력 (**추정**: DIP·한영 등) |
| `$0400` (쓰기) | 보낼 문자를 쓰고 `$43EE`에 사본 저장. 기능키 줄(`$43C0,X`) 글자를 하나씩 여기로 보냄 | **메인 CPU로 가는 키 코드 래치** (**추정**, 메인 `$C000`에서 읽힘) |
| `$0800` (쓰기) | 초기화 때 `$82` | 제어 래치 (**미상**) |
| `$0C00` (쓰기) | `$8800` 값을 표로 바꿔 씀 | 비디오/모드 래치 (**추정**: U69 74LS273) |
| `$0000–$03FF` | `STX $02 / STY $0002 / STX $03`가 반복해서 나옴 | 일반 RAM이 아님 (**추정**). U64는 따로 작업 RAM이 없고 변수를 U68 꼭대기에 둔다 |
| `$C000–$DFFF` (+`$E000–$FFFF`) | 펌웨어 | U65 |

* 결론: **U64가 키보드를 직접 스캔하는 키보드 컨트롤러**이기도 합니다. Disp 키가 메인 CPU와 상관없이 기능키 줄을 바꾸던 현상([08](08-repair-log.md), [09](09-verified-baseline.md))과 맞습니다.
* 기능키는 **매크로**로 보입니다: F 키를 누르면 U64가 기능키 줄(행 24)의 라벨 글자를 `$0400`으로 한 글자씩 보내, 메인 CPU에는 그 글자를 친 것처럼 들어갑니다 (**추정**).

## 3. U68은 두 CPU가 함께 쓰는 80컬럼 화면 메모리

메인 쪽 80컬럼 펌웨어(U45 `$C300–$C3FF`, `$C800–$CFFF`)는 Videx 카드 하드웨어(`$C0B0` CRTC, `$CC00` 화면 RAM)를 **전혀 쓰지 않습니다**. 대신 **`$E000–$E7FF`**를 씁니다 (**확인**: `LDA $E780,Y`, `STA $E7D2,Y`, `ORA $E7EC` 등).

| 메인 CPU 주소 | 내용 |
| :--- | :--- |
| `$E000–$E77F` | 80컬럼 × 24행 화면 (한 행 80바이트, 선형) |
| `$E780–$E7CF` | 행 24 = **기능키 줄** (80글자. `$C315–$C398`이 이 줄을 편집, `CPY #$4F`) |
| `$E7D0–$E7FF` | 80컬럼 펌웨어 변수 (`$E7D2,Y` = 기능키 12개 위치표, `$E7EA` = 기능키 번호, `$E7EC` = 상태) |

### 3.1 U68 주소 핀 배선 (측정, 2026-11-24)

U68 A0–A10은 모두 74LS157(U47·U58·U59) 출력에서 옵니다. 세 칩은 /G가 GND라 항상 켜져 있습니다. SELECT(핀 1) 셋은 한 넷이고, SELECT가 Low이면 A 입력(U64 쪽), High이면 B 입력(메인 쪽)을 고릅니다. B 입력은 모두 메인 주소 버퍼(U31·U32·U33, 74LS367)를 거쳐 메인 CPU 주소선에 붙습니다.

| U68 | MUX | A 입력 (U64 쪽) | B 입력 경로 | 메인 주소 |
| :--- | :--- | :--- | :--- | :--- |
| A0 | U58 1Y | U64 A7 | U31 9←10 | A8 |
| A1 | U59 4Y | U64 A9 | U32 11←12 | A10 |
| A2 | U59 3Y | U64 A4 | U32 13←14 | A5 |
| A3 | U59 2Y | U64 A5 | U31 5←4 | A6 |
| A4 | U59 1Y | U64 A8 | U31 7←6 | A9 |
| A5 | U58 2Y | U64 A6 | U32 9←10 | A7 |
| A6 | U47 1Y | U64 A2 | U31 3←2 | A3 |
| A7 | U47 2Y | U64 A1 | U32 3←2 | A2 |
| A8 | U47 3Y | **NOR(U64 A12, Φ0)** (U48 3Y) | U33 3←2 | A0 |
| A9 | U47 4Y | U64 A0 | U33 13←14 | A1 |
| A10 | U58 4Y | U64 A3 | U31 13←14 | A4 |

* 양쪽 모두 순서가 섞여 붙지만, A8을 뺀 10개 핀 모두에서 **U64 A(k−1) ↔ 메인 Ak**가 성립합니다. 섞임이 서로 상쇄되므로 두 CPU 사이 대응은 비트 순서와 상관없이 정해집니다.
* U68 A8(U64 쪽)은 U48(74LS02) 3Y = NOR(U64 A12, Φ0)입니다. Φ0는 U33-4(버퍼 전 메인 Φ0)입니다. Φ0가 Low인 반주기에 A8 = /A12입니다. (처음에 U47-11이 어디에도 안 붙은 것처럼 측정됐으나, 나중에 U48-10과 도통으로 정정.)
* 따라서 U64가 U68을 쓰는 반주기에는 다음과 같습니다.

```
메인 $E000 + n   ↔   U68 바이트 n (메인 주소 순서로 본 위치)
U64  $4000 + k   ↔   메인 $E000 + 2k + 1   (홀수 칸, A12=0 → A8=1)
U64  $5000 + k   ↔   메인 $E000 + 2k       (짝수 칸, A12=1 → A8=0)
```

* 처음 롬 코드만 보고 세운 대응(`$4000` = 짝수, `$5000` = 홀수)과 **반대**입니다. 아래 3.3의 변수 대응표는 그 옛 추정이라 다시 맞춰야 합니다.
* 에뮬레이터: U68을 메인 주소 순서(`n`)로 2KB 배열 하나로 두고, U64 쪽 접근은 `n = (k << 1) | (A12 ? 0 : 1)`로 바꿉니다. 화면 표시 순서가 메인 순서와 같은지는 비디오 카운터 쪽 확인이 필요합니다.

### 3.2 메인 CPU가 U68을 보는 조건 (측정 진행 중)

**SELECT = U51(82S129, 라벨 "2") O2(핀 11)**. 덤프에서 정리한 논리식(256개 전부 확인)은 다음과 같습니다.

> O2 = A5 · A3 · A2 · /A1 · /(A7 · A4)  (A0, A6 무관)
> 칩 핀으로: 핀 2·4·7 = High, 핀 6 = Low, 핀 15와 핀 3이 동시에 High가 아님

| U51 핀 (주소 비트) | 연결 (측정) | SELECT 조건 |
| :--- | :--- | :--- |
| 1 (A6) | U64 R/W | 무관 |
| 2 (A5) | U48 1Y = NOR(48-2, 48-3) | High |
| 3 (A4) | ? | 핀 15와 동시 High 금지 |
| 4 (A3) | U77 1Y2 | High |
| 5 (A0) | ? | 무관 |
| 6 (A1) | U35 2Y2 (/2G = U34 2Y = NAND(Φ0, 34-5), 2B = U36 O1, 2A = U36 O2) | Low → Φ0 High · 34-5(= U49 2Q) High · U36 핀 1·6 High · 핀 2·7 Low (U36 덤프, 2026-11-26). U36 입력: 1 = U51 O4, 6 = A13, 2 = NAND(A15, A14), 7 = GND → **2Y2 = Φ0 · U49 2Q · U51 O4 · `$E000–$FFFF`** |
| 7 (A2) | Φ0 (U33-4) | High → 메인 Φ0 반주기에만 |
| 15 (A7) | U48 2Y = NOR(U62 /2Q, 48-6) | 핀 3과 동시 High 금지 |

**U62 2번 플립플롭 (Videx식 스위치)**: D = GND, /CLR = +5V(U30 SO), /Q → U35 /1G, U48-5.

| 동작 | 신호 | 조건 |
| :--- | :--- | :--- |
| 켜기 (/PRE) | U22(74LS138) Y3 | A15·A14 = 11 (U34 NAND → U50 핀 1), A13 = 0 (U50 핀 5), A11 = 0 (U22 /G2B), A10–A8 = 011 (U22 A·B·C), U76 /2Q 타이밍 (U22 /G2A) → **`$C300–$C3FF`** |
| 끄기 (CLK) | U35 1Y3 | 스위치가 켜진 동안 A10·A9 = 11 접근이 끝날 때 (`$CE00–$CFFF` 포함, 상위 주소 조건 없음) |

* U22 G1 = U50 O4. U50 덤프에서 O4 = /핀5 · /핀1 (U50 A1 핀 6은 GND 고정).
* U22 디코드에서 A12는 아직 어느 조건에도 보이지 않습니다. 그대로면 `$D3xx`에서도 켜집니다.
* U76 2번 FF는 J = U74 1Y, /K = 그 반전(U72), /PRE·/CLR = +5V → T 플립플롭(분주기). U22를 정해진 클럭 구간에만 켜는 타이밍 신호로 봅니다.
* **U45 코드 대조 (2026-11-25)**: `$C300` 진입은 Videx와 같습니다(`BIT $FFCB` → `STA $CFFF` → `JSR $CAA7`). `$C315–$C3DF` 기능키 편집 루틴은 `$C3xx`에서 실행되면서 `$E7xx` 변수를 계속 읽고 씁니다. 그때마다 스위치가 꺼져도 다음 명령을 `$C3xx`에서 가져오면 다시 켜지므로 동작에는 문제없습니다. `$C800–$CBFF` 코드의 절대 주소 접근은 `$E7xx` 변수 8곳뿐이고, 화면은 `($28),Y` 같은 간접 주소로 씁니다.
* **극성 문제 (미해결)**: U62 /Q는 U48 NOR를 거쳐 U51 핀 15로 갑니다. 그래서 스위치가 **꺼져 있을 때**(/Q = 1) 핀 15 = 0이 되어 SELECT 조건 하나가 풀립니다. "켜져 있을 때만 메인이 U68을 본다"는 해석과 반대입니다. U51 핀 3, U48 핀 2·3·6, U35 2번 디코더·U77 1번 디코더 입력을 재야 판정됩니다 → [14](14-measure-todo.md) A절.

### 3.3 옛 변수 대응 (롬 코드 기준 추정, 3.1 측정과 짝/홀이 반대라 재검토 필요)

| 메인 쪽 | U64 쪽 (옛 추정) | 양쪽 코드 |
| :--- | :--- | :--- |
| `$E780` 행 24 시작 | `$43C0` / `$53C0` | 메인이 기능키 줄 작성 ↔ U64가 `$43C0,X`·`$53C0,X`로 읽음 |
| `$E7D0` | `$43E8` | 메인 `INC $E7D0` ↔ U64 `STA/ORA $43E8` |
| `$E7D2,Y` | `$43E9+` | 메인 기능키 위치표 ↔ U64 `$43E9–$43F5` 사용 |
| `$E7EA` | `$43F5` | 메인 기능키 번호 ↔ U64 `LDX $43F5` |
| `$E7EC` | `$43F6` | 메인 상태 비트7 ↔ U64 `LDY/AND/STA $43F6` |

3.1 측정대로라면 `$E7D0`(짝수)은 U64 `$53E8`, `$E7EC`는 `$53F6`에 대응합니다. U65 코드에서 `$53E8,X`·`$53E9,X`로 기능키 위치표의 차이를 구하는 부분(`$E83F–$E864`)과 맞는지 다시 대조해야 합니다.

### 남은 의문 (메인 쪽)

* 메인 `$E000–$E7FF`는 원래 U46(Applesoft 후반부) 롬 자리입니다. 어떤 조건에서 이 2KB가 롬 대신 U68로 바뀌는지는 3.2의 SELECT 조건과 U46 /CE·/OE를 확인해야 확정됩니다.

## 4. 에뮬레이터에 필요한 것 (다음 단계)

1. **U64 6502 하나 더**: U65를 `$C000`/`$E000`에, U68을 3.1 대응대로 `$4000`/`$5000`에, 키보드 행 `$8000–$800C`, 스위치 `$8800`, 래치 `$0400/$0800/$0C00`.
2. **메인 쪽**: U68을 `$E000–$E7FF`에 언제 보이게 할지(3절 의문), `$0400` 래치를 메인 `$C000` 키 입력으로 연결.
3. **화면**: U68 80×25를 U70 폰트로 그리기(행 24 = 기능키 줄). 한글 조합(뱅크 3)은 U65의 변환 루틴 해석 후.
4. **키보드**: PC 키 → HART 키 매트릭스(13행 × 8열) 표. 행·열 배치는 J10 배선([05](05-interface-pinouts.md))과 U65 스캔 루틴의 키 코드표에서 만들어야 함.
