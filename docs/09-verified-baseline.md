# 09. 확인된 사항과 정상 기준값

다시 비정상 동작할 때 **이 문서부터** 봅니다. 지금까지 측정으로 **확인된 것만** 모았습니다. 추정이나 측정 실수로 판명된 값은 넣지 않았고, 아직 확정되지 않은 값은 맨 아래 "미확정"에 따로 두었습니다. 날짜별 원자료는 [08 수리 기록](08-repair-log.md), 전원을 끄고 잰 연결은 [`data/netlist.csv`](../data/netlist.csv)에 있습니다.

## 2. 정상 기준값 (전원 켠 상태)

측정 조건: **검정 프로브는 GND** (U30 핀 1, U72 핀 7, 슬롯 핀 26 중 하나, 키보드 쪽은 키보드 단자 16). Hz는 **숫자가 자리 잡을 때까지 몇 초 기다린 값**.

### CPU 동작

| 측정 위치 | 정상 값 | 뜻 |
| --- | --- | --- |
| U30 핀 25 (A15) DC | 3.9–5V, 계속 변함 | CPU가 ROM 코드를 실행 중. **고장 때는 0.7V였음** |
| 화면 | HART 로고 + "Zung Won Co.,Ltd. 542-3675 SEOUL KOREA" + 맨 아래 기능키 이름 줄 | ROM·CPU·RAM·문자 발생·비디오 동작 |

### 키보드 (케이블 연결, 전원 ON)

| 측정 위치 | 정상 값 |
| --- | --- |
| 74LS145 15·14·13·12번 (행 번호 A·B·C·D) Hz | 44.7 / 94 / 105 / 46 kHz (넷 다 움직이면 정상, 반씩 줄지는 않음) |

| 항목 | 확인된 내용 | 근거 |
| --- | --- | --- |
| CPU 클럭 경로 | 타이밍 → U33(74LS367) 핀 4 → 핀 5 → 저항 R1(1kΩ, 반대쪽 GND = 풀다운) → 비아 → U30 핀 37 | 도통·저항 측정, 앞뒷면 겹친 그림 [`u30_pin37_overlay`](../analysis/u30_pin37_overlay.jpg) |

| 두 6502 | U30(메인)과 U64(한글)는 데이터 버스·클럭·리셋이 서로 분리 (각자 RES 1kΩ 풀업) | 도통·저항 |
| U64 데이터 버스 | U65 "VD5" D0, U67 74LS245 A2와 연결 | 도통 |
| 슬롯 방향 | 앞면 슬롯 위쪽 기준 각 슬롯 왼쪽 줄 26(위)→50(아래), 오른쪽 줄 25→1. 슬롯1 = 왼쪽 끝 | 측정 |
| 칩 1번 핀 | 세로 칩 = 오른쪽 아래, 가로 칩 = 왼쪽 아래 (앞면 슬롯 위쪽 기준) | 노치·도통 |
| 키보드 단자 J10 | 핀별 신호 표: [05 "키보드 단자 J10"](05-interface-pinouts.md). GND = 케이스 반대쪽 끝 2핀, +5V = 케이스 쪽 끝 왼쪽 핀 | 슬롯 25·26과 도통 |
| 키보드 케이블 | 14가닥 모두 정상, 결선은 05 문서 표. 공장 배선(원래 짝 키보드) | 도통 |
| 키보드 방식 | 본체가 행 번호 4비트(A–D)를 보내고 키보드 74LS145가 행을 고름, 열 8가닥으로 돌아옴 (본체가 매트릭스 직접 스캔) | 분해·측정 |
| RESET 키 | 매트릭스 키: 74LS145 3번(행 2) × 열 단자 10. 누름 0Ω / 뗌 O.L | 케이블 뽑고 Ω |
| 전원 선 색 (PSU) | **빨강 = +12V**, 주황 = +5V, 초록 = −12V, 파랑 = −5V, 검정 = GND (일반 관례와 다름) | 실물 확인 |

## 4. 측정에서 배운 것 (같은 실수 반복 방지)

| 실수 | 결과 | 올바른 방법 |
| --- | --- | --- |
| Hz를 바로 읽음 / 검정 프로브가 GND가 아님 | 3.585MHz, 70kHz, 60Hz 같은 엉뚱한 값 → "Φ0 끊김" 오판 | 검정 프로브 GND, 몇 초 기다린 뒤 읽기 |
| 짧은 펄스를 Hz로 잼 | 키보드 스캔 펄스가 0Hz로 나옴 | **DC V로 평균 비교** (누름/뗌) |
| 떠 있는 핀(오픈 컬렉터 출력, 키 안 누름)을 잼 | 60Hz 잡음 | 키를 누른 상태에서 열 쪽을 잼 |
| "O.L"을 0Ω으로 읽음 | 스위치가 붙었다고 오판 | O.L = 안 통함 |
| 프로브가 덜 닿음 | 74LS145 Vcc 0V로 오판 | 이상한 값은 한 번 더 재기 |
| 케이블 꽂은 채 도통 | 본체 회로를 거쳐 통하는 것처럼 보임 | 도통은 케이블 뽑고 |
| 소켓·단자 번호 방향 착각 | 케이블 "2가닥 끊김" 오판 | 기준 그림([소켓](../analysis/kbd_cable_socket_numbered.jpg), [키보드](../analysis/kbd_measure_simple.jpg)) 번호만 사용 |

## 5. 다시 고장 났을 때 점검 순서

1. **전원 끄고 10초 이상 기다렸다가 켜기** (바로 껐다 켜면 리셋이 약하게 걸릴 수 있음)
2. 화면이 안 나오면: 전원 끄고 **소켓 칩 꾹 누르기** (이번에 이것으로 해결)
3. **+5V** (U30 핀 8): 4.75V 아래면 전원부
4. **A15** (U30 핀 25 DC): 0.7V 근처면 CPU가 ROM을 못 돌림 → 클럭(U30 핀 37 약 1MHz, 7M 약 7MHz) 확인
5. 키가 안 먹으면: **케이블 다시 꽂기** → Ctrl+RESET "삑" 확인 → 위 2절 키보드 기준값과 비교
6. 위 값들이 모두 기준값과 같으면 2절 이후 바뀐 곳(새로 꽂은 카드, 드라이브 등)을 의심
