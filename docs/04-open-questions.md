# 04. 미확인 사항

아래 항목은 사진만으로 판단할 수 없어 측정이나 ROM 덤프가 필요합니다. 확인되면 체크하고 결과를 해당 문서에 반영하세요.

- [x] **두 번째 6502(U64)의 역할**: 독립적으로 동작하며 한글 폰트 처리를 담당 (2026-11-06 측정 확인) → [07](07-back-trace-notes.md)
    - 역광 사진으로 세웠던 "리셋 고정 예비 CPU" 추정은 기각
    - 근거: U30↔U64 D7(핀 26) 불통, Z80↔U64 주소선 공유 없음, U30과 U64 클럭 다름 → `data/netlist.csv`
- [ ] **U64 서브시스템 구성**: U64 전용 ROM/RAM(U65 VD5 데이터선 연결 확인·A0 직결 아님, U70 CHR P4·U68 6116은 D0 직결 아님), 클럭 출처와 주파수, U30과 데이터를 주고받는 경로
- [ ] **U65 "VD5"(2764)의 내용**: U64 데이터 버스에 연결됨. U64 프로그램인지 한글 폰트인지 덤프로 확인
- [x] **CPU 3개의 관계**: U30(Apple 프로그램), U2(CP/M), U64(한글 폰트)가 각각 따로 동작 (2026-11-06 확인)
- [ ] **Z80 서브시스템 동작 방식**: CP/M 실행은 확인 (2026-11-06). 6502와 버스를 어떻게 나누는지(SoftCard식 DMA인지), 어떤 주소로 전환되는지는 미확인
- [ ] **HM6116(U68) 2KB SRAM의 용도**: 80컬럼 화면 버퍼 또는 한글 폰트 RAM
- [ ] **2764 "CHR P4"(U70)의 내용**: 한글 폰트인지 80컬럼 문자인지 (덤프하면 바로 확인 가능)
- [ ] **PROM 내용**: U17, U18 "M", U36 "3", U50 "1", U51 "2" (모두 16핀 Signetics 82S129 계열로 판단, 덤프 필요)
- [x] **U69(8452D0)**: 74LS273으로 확인 (앞면 확대 사진 212301)
- [x] **J2·J3 용도**: 내장 FDD 드라이브 단자 2개 (사용자 확인 2026-11-07). 옆의 U16–U20이 Disk II 방식 컨트롤러
- [ ] **내장 FDD 세부**: 어느 쪽이 드라이브 1인지, 핀 1 방향, 각 핀 전압(GND·+5V·+12V·−12V 위치), 동작 슬롯 번호(보통 6), U17·U18 PROM 내용
- [x] **J10(2×8 라이트앵글) 용도**: 키보드 단자로 확정 (키보드 케이블이 꽂혀 있었음, 2026-11-07) → [08](08-repair-log.md). J6는 RGB 출력으로 확인
- [x] **키보드 동작 (2026-11-08)**: 정상 동작 확인 (키 입력, Ctrl+RESET "삑"). 케이블 14가닥 결선 전부 확인, 스캔 신호·전원·열 선·RESET 경로 정상. 일부 키는 스위치 접점 불량(청소 필요). 결론 표: [08 "키보드 진단 결론"](08-repair-log.md), 결선: README "키보드"
- [ ] **J10 키보드 핀 배치 (본체 쪽)**: GND(케이스 반대쪽 끝 2핀)·+5V(케이스 쪽 끝 왼쪽) 확인. 케이블 결선을 통해 각 J10 핀이 키보드 어느 단자(A·B·C·D 행 번호, 열 8가닥)로 가는지는 알 수 있음. 남은 것: J10 열 핀 ↔ U80·U81 입력 핀·SIP 통전, A–D를 내보내는 본체 칩 → [그림](../analysis/j10_keyboard_back.jpg)
- [ ] **Ctrl+RESET 뒤 화면 유지**: "삑"은 나지만 HART 로고 화면 그대로. 디스크 대기/모드 선택 화면으로 추정 → 기능키·Return·Disp·Vdx 시험, 부팅 디스크로 시험
- [ ] **Vdx 키**: Videx 호환 80컬럼 화면 전환 추정. 보드에서 6845(Videx 카드의 화면 칩)는 못 찾음 → 80컬럼은 U64·U65·U70·U68 쪽 추정
- [ ] **(완료된 항목 포함, 기록용) 키보드 측정 목록 (2026-11-07)** — 그림 [`analysis/kbd_measure_simple.jpg`](../analysis/kbd_measure_simple.jpg) 번호 기준, 케이블 본체에서 뺀 채 통전 모드. 지금까지 결과는 [08 수리 기록](08-repair-log.md) "키보드 양면 사진 판독" 항목.
    1. ~~74LS145 14번(B) ↔ 단자 12 재확인~~ → 통전 확인 (2026-11-07). B = 단자 12 확정
    2. 부품면 저항 1개 ([위치 그림](../analysis/kbd_resistor_location.jpg)): 두 다리가 각각 어디와 통하는지 (단자 1–16, 74LS03 1·10·12번)
    3. (일부 완료 2026-11-08: 열 선 = 단자 2·3·4·5·10·13·14·15, 모두 4.9V 풀업. 단자 1은 케이블에 선 없음 추정) 남은 단자 1·2·3·4·5·10·13·14·15 (열 선 후보): 키를 누른 채 단자 ↔ 74LS145 출력핀(1–7, 9–11)·74LS03 출력핀(3·6·8·11) 통전
    4. ~~초록 선: Reset 키를 누른 채 초록 ↔ 검정~~ → 통전 없음 (2026-11-07). RESET 키 한쪽 다리 = 단자 16(GND) 상시 통전. 남은 것: RESET 키를 누른 채 단자 16 ↔ 단자 1–15 (누를 때만 삑 하는 단자 = RESET 선) → **해당 단자 없음** (2026-11-07). → RESET 패드(납땜면 [그림](../analysis/kbd_solder_overview.jpg) 빨간 칸 왼쪽 가운데)는 누를 때 **단자 10**과 통전 = 매트릭스 키. → 그 패드 = **74LS145 3번(Y2)** → **RESET = 행 2 × 열 단자 10 확정** (2026-11-07). 같은 방법(키 누른 채 패드 ↔ 단자, 반대 패드 ↔ 칩 출력)으로 다른 키도 찾을 수 있음. 다음: 납땜면 RESET 스위치 두 패드 사이를 누른 채 직접 통전(스위치 자체 동작 확인) → 동작하면 GND 아닌 쪽 패드 ↔ 초록 선·저항 다리·74LS145/74LS03 모든 핀. 초록·검정 선 용도는 미확인
    6. **(선택, 미측정)** Disp·Ctrl 키의 행 × 열 — 원래 목적(Ctrl+RESET이 안 먹는 원인 가르기)은 2026-11-08 Ctrl+RESET 정상 동작으로 해소. 남은 의미는 기록용: Ctrl이 매트릭스 키인지 따로 가는 선인지(초록·검정 직결 선 후보), Ctrl+RESET 조합을 하드웨어가 판정하는지 ROM이 판정하는지. 방법: 전원 ON·케이블 연결, Ctrl 누른 채 열 단자 2·3·4·5·10·13·14·15 DC V → 내려가는 단자가 Ctrl 열 (2026-11-08 측정은 중간에 멈춤, 안 누른 값만 4.9V 기록)
    5. **(완료 2026-11-08: 14가닥 전부 확인, 정상)** 케이블 양 끝 대응: 키보드 단자 번호 ↔ 본체 쪽 커넥터 구멍 (본체 J10 GND 끝 기준). 꽂는 방향은 결정됨 ([`analysis/kbd_plug_direction.jpg`](../analysis/kbd_plug_direction.jpg)). 본체 쪽 커넥터 구멍 번호 기준: [`analysis/kbd_cable_holes_numbered.jpg`](../analysis/kbd_cable_holes_numbered.jpg) (1번 +5V, 8·9번 GND). 결과 표: [05 "키보드 단자 J10"](05-interface-pinouts.md)
        - **측정 (2026-11-07, 사용자)**: 본체 쪽 커넥터에서 **글자(JAE…) 찍힌 면 쪽 줄**의 양 끝 구멍 — 한쪽 끝 = GND(키보드 단자 16), 반대쪽 끝 = +5V(키보드 단자 9). (안내 그림 2번 사진 기준 위 = GND, 아래 = +5V.) → GND·+5V가 같은 줄 양 끝. **J10 +5V 확인 (2026-11-07, 사용자)**: 케이스 쪽 끝 **왼쪽 핀(SIP·U80 반대쪽 줄)** = +5V. → 꽂는 방향 결정: 커넥터 글자 면 줄 → J10 왼쪽 줄, GND 끝 → 케이스 반대쪽. 그림 [`analysis/kbd_plug_direction.jpg`](../analysis/kbd_plug_direction.jpg). 꽂은 뒤 전원 켜기 전 통전 확인(단자 9↔슬롯1 25, 단자 16↔슬롯1 26, 9↔16 안 통함). J10 GND는 케이스 반대쪽 끝 2핀이므로, 예상대로 J10 +5V가 케이스 쪽 끝이면 글자 면 줄을 그 +5V 핀 줄에 맞추고 GND 끝을 케이스 반대쪽으로 꽂으면 됨.
- [ ] **키보드 방식**: 키보드 안에 74LS145·74LS03만 있음 → 본체가 매트릭스를 직접 스캔 (2026-11-07 분해, 2026-11-08 스캔 신호 측정으로 확인). 열 선 8가닥(추정). 행 번호 4비트를 내보내는 본체 칩, 74LS03 용도, 초록·검정 직결 선이 어느 키인지(Disp 추정, RESET 아님) 미확인
- [ ] **모델명 "ZPC-40"**: 키보드 명판에 "PERSONAL COMPUTER ZPC-40". 본체 모델명인지 확인 (케이스 라벨·ROM 문자열)
- [ ] **U80·U81(74LS257) 용도**: 비디오 MUX로 분류했으나 J10 바로 옆이라 키보드 데이터 입력 후보. J10 옆 SIP 9핀(저항 어레이 추정)과 미실장 구멍 7개 용도도 미확인
- [ ] **J6 RGB 핀 배치**: 5핀 중 R/G/B/동기/GND 배치, 직렬 저항 실제 값(330k/12k로 판독됨), 디지털(TTL) RGB인지
- [ ] **카세트 잭 J4/J5**: 어느 쪽이 IN(LM339 경로), 어느 쪽이 OUT인지
- [ ] **슬롯 번호**: SL1–SL4가 Apple II 슬롯 몇 번에 해당하는지
- [x] **슬롯 핀 방향**: 앞면 기준 왼쪽 줄 26(위)–50(아래), 오른쪽 줄 25–1. 핀 50 = +12V 네 슬롯 확인 (2026-11-07) → [05](05-interface-pinouts.md)
- [x] **CPU 박자(Φ0) 경로**: U33 74LS367 핀 4 → 핀 5 → U30 핀 37, R1 1kΩ 풀다운. 슬롯 Φ0와 직결 아님 (2026-11-07) → [02](02-system-architecture.md)
- [ ] **U33 핀 4(CPU 박자 버퍼 입력)의 출처**: 슬롯 Φ0와 직결 아님. 어느 타이밍 칩 출력인지 미확인
- [ ] **슬롯 Φ0를 만드는 칩**: U78 핀 1·U1 핀 11과 연결 확인. 구동하는 출력은 미확인
- [ ] **테스터 Hz 재측정 필요**: 슬롯 핀 37(Q3) 68kHz, U64 핀 37 69kHz는 측정 방법(기준점·안정 대기)이 확립되기 전 값 → 다시 재야 함
- [ ] **간헐 부팅 실패**: 가끔 까만 화면으로 멈춤. 리셋 회로·남은 소켓 접촉·+5V 여유 중 원인 미확인 → [README](../README.md) "알려진 문제"
- [ ] **U30 리셋 회로**: RES 1kΩ 풀업 확인. 전원 켤 때 RES를 Low로 잡는 부품(콘덴서·리셋 IC·RESET 키) 위치 미확인
- [ ] **J1 핀 순서**: 5핀 각각의 전압 (선 색은 확인, 핀 위치 미확인)
- [ ] **−12V, −5V 레일**: 슬롯 핀 33·34 미측정
- [ ] **시스템 ROM 주소 범위**: "C/D8"과 "EF5" 라벨이 주소 범위를 뜻하는지
